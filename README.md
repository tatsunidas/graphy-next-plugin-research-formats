# 研究用画像形式の書き出し — GRAPHY-Next プラグイン

[GRAPHY-Next](https://github.com/tatsunidas/GRAPHY-Next) のシリーズを、研究で使われる画像形式で書き出すプラグインです。
形式を順に増やします。現在は **NIfTI の 2 ファイル形式（`.hdr` ＋ `.img`）** と **BIDS データセット（MR の anat。ZIP）** です。

> **研究・教育用です。診断機器ではありません。** 診断・治療の判断には使わないでください。
> 書き出したファイルには患者情報（氏名・ID・日付など）を書きません。ファイルの取り違えは利用者側で管理してください。

- 対象: GRAPHY-Next **0.6.3 以降**（host API **H78** `host.nifti.exportSeries` を使います）
- 動作モード: **デスクトップ版（standalone）のみ**
- 出る場所: メイン画面の **Plug-ins** メニュー →「研究用画像形式の書き出し」

## 使い方（NIfTI 2 ファイル形式）
1. 形式で「NIfTI 2 ファイル形式」を選び、**シリーズを選ぶ**（本体の選択窓。検索・絞り込みができます）
2. **保存先のフォルダ**と**ファイル名**を決める（既定 `volume`。`.hdr` / `.img` が付きます）
3. **書き出す**

- 向き（患者座標 LPS ↔ NIfTI の RAS+）は、本体の「NIfTI で書き出し」が 1 か所で決めます。このプラグインは向きに触りません。
  4 次元（動態・時相つき）も書き出せます。
- 本体の書き出しが断る形（ガントリーチルト・モザイク・間隔が不揃い・焼き込みの多い種類など）は、理由を画面に出して何も保存しません。
- `.hdr`（348 バイト）と `.img`（float32・リトルエンディアンの生の画素）の両方を作れてから、選んだフォルダへ保存します。
- **同じ名前のファイルがあっても上書きしません。** `.hdr` と `.img` の両方に同名のファイルがあるときは、本体が 2 つとも `名前 (2)` のように別名で保存します（画面に保存した名前を出します）。片方だけ同名のファイルがある場合は名前が食い違うことがあり、そのときは画面が警告します。空の新しいフォルダを選ぶのが確実です。

## 使い方（BIDS データセット）
1. 形式で「BIDS データセット」を選び、**データセット名**（英数字・空白・`-` `_`。**氏名・患者 ID を入れないでください**）と、任意の説明を入れる
2. **シリーズを 1 本ずつ追加する**: 種類（suffix）・被験者番号（既定 1）・セッション番号（空なら無し）を決めて［シリーズを追加…］→ 本体の選択窓でシリーズを選ぶ
   （プラグインにはシリーズの記述が渡らないため、選んだ直後に種類を決める作りです）
3. **書き出す** → 保存ダイアログで ZIP を保存。展開して使います。

- 被験者は**連番**（`sub-001`…）です。患者 ID・氏名・日付はファイル名にも中身にも出ません。複数の被験者のシリーズを入れるときは、被験者番号を変えてください（プラグインは患者を区別できません）。
- 同じ被験者・セッション・種類のシリーズが複数あるときは、`run-01`、`run-02`… が付きます。
- 中身: `dataset_description.json`（`Name`・`BIDSVersion`・`DatasetType`）・`participants.tsv`（`participant_id` の列だけ）・`README`・`sub-*/[ses-*/]anat/*.nii.gz`。画像は本体が書いた NIfTI（float32）をそのまま入れます。
- **対象は MR の anat（3 次元）だけ**です。種類は `T1w` `T2w` `FLAIR` `PDw` `PDT2` `T2starw` `UNIT1` `angio` `inplaneT1` `inplaneT2`。
  - 時相つき（4 次元）の画像は anat にできないので断ります。入力の合計が 1 GiB を超えるときも断ります（本体の保存ダイアログの仕組みは、成果物をいったん画面のメモリへ取り込むため、数 GB の ZIP に向きません。シリーズを分けて書き出してください）。
  - **プラグインはシリーズの種類（モダリティ）を判定できません。** MR 以外のシリーズを追加しないでください（CT などは BIDS の仕様にありません）。
  - **DWI・func・fmap・perf・PET・CT は対象外**です。DWI は `.bval`/`.bvec`、func は `RepetitionTime` と `TaskName` が必須で、本体が DICOM のタグをプラグインに渡す仕組みが無いため作れません。CT は BIDS の仕様に出てきません。
  - **取得パラメータ（TR・TE・FlipAngle など）の JSON は作りません**（値を作らないため）。`dataset_description.json` の `Authors` も書かないので、検証器は警告を出します。

## しくみ
- BIDS は、NIfTI を `host.nifti.exportSeries` で 1 本ずつ作り、JAR が ZIP に詰めます（`.nii.gz` は圧縮済みなので再圧縮しません）。本体の保存 API は入れ子のフォルダを作れないため、データセット全体を 1 つの ZIP にして保存ダイアログで保存します。
- 本体の `host.nifti.exportSeries`（H78）が、匿名化の出力から NIfTI（`.nii.gz`・float32）を一時フォルダへ作ります。
- バックエンド面（Java JAR。依存は JDK と GraphyPlugin SPI だけ）が、そのファイルを `.hdr` / `.img` に直します。成果物は 1 ジョブ 1 ファイルなので、`.img`（長さを全部検査）→ `.hdr` の順に 2 回走らせます。
  - 想定外の形（NIfTI-2・拡張つき・float32 以外・画素の長さの食い違い・壊れた gzip）は、何も書かずに理由コードで断ります。
  - 本体が置いた一時フォルダの下の `.nii.gz` だけを読みます（任意のファイルは読みません）。
- 使い終わった一時ファイルは、成功・失敗・中止のいずれでも片付けます。

## 開発
```bash
# GraphyPlugin SPI（GRAPHY-Next の Release の graphy-plugin-api-<ver>.jar）をローカルに登録してから
mvn -f backend/pom.xml -Dgraphy.version=0.6.3 package     # 合成 NIfTI の単体テスト
```
`ui.js` は単一ファイルでそのまま配信されます（ビルドはありません）。
